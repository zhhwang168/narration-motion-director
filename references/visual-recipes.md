# Choose a visible transformation

Choose the scene from the action in the narration. These are options to adapt, not a sequence to repeat in every chapter.

| Spoken idea | Visible action and consequence | Useful shot form |
| --- | --- | --- |
| Attach the notes | File enters the workspace, opens at the relevant passage | Document close-up followed by contextual view |
| Separate confirmed facts from open questions | Extract statements; move the unknown into an unresolved group | Source-to-fact transformation |
| Wi-Fi is still unconfirmed | Mark this line as unresolved; keep the venue question visible | Focused annotation with a stable read hold |
| Remove private details | Redact the private fields; retain the useful arrangements | Before/after document edit |
| Shorten the introduction | Select excess lines, compress the opening, move equipment earlier | Editable outline reorder |
| Connect a microphone | Cable docks, level responds to speech, headphones indicate listening | Object action → meter → result |
| Ask for four columns | Grow the table, fill one row from narration, flag missing material | Table construction, not cards labelled with columns |
| Use tools for a result | Task goes to the appropriate tool and returns a specific artifact | Focused handoff with one input and output |
| Keep the latest version | Compare versions, choose approved source, archive obsolete branch visually | Version selection |
| Product reveal | Establish silhouette, move camera to reveal material, land product, then title | 3D or layered reveal justified by subject |

## Example: three facts, actual progression

When the narration names room, projector, and Wi-Fi in turn, reveal each fact at its corresponding cue. When it asks to separate facts from questions, move the two confirmed facts into a confirmed group and leave Wi-Fi unresolved. When it asks the venue, turn the unresolved line into a question addressed to the venue. Each new action changes the state; no looping highlights are needed.

## Attention and continuity

For a character example, see the [cat-and-fish cue plan](../examples/cat-and-fish-cue-plan.json). The eyes establish the goal, the paw makes contact before the fish moves, and the surprised reaction holds before concealment. Those example frames are storyboard estimates, not timings to copy into an unrelated recording.

Use one primary focus per beat. Let the previous scene's object become the next scene's input where the story connects. Alternate wide context and focused detail when it helps explain a change. Vary scene grammar when the explanation changes, rather than scheduling a new visual style every few seconds.

A useful animation often has preparation → action → response → settled result. Not every beat needs all four phases; a short highlight may suffice for a small correction. Timing must allow viewers to read and connect the result to the spoken explanation. For a dense table, static camera and staged row reveals can be more effective than parallax.

Real software instructions need actual source screens where available. If a conceptual diagram is used, identify it as illustrative and avoid inventing current product controls or claiming clicks were demonstrated. Keep real labels large enough to read, show the pointer action and resulting state, and preserve enough context to locate the control.

## Typography and presenter

For kinetic typography, keep a complete layout underneath the animation so later glyphs do not reflow earlier ones. Reveal by opacity and controlled offset inside fixed final positions. Spaces, punctuation, mixed Chinese/English fonts, and wrapped lines need explicit inspection. Do not apply a separate spring to each character's layout width.

Reserve a consistent presenter region for recurring introductions and explanations. If the scene needs that region, move the presenter at a cut or hide it briefly when authorized. Do not shrink important content to illegibility to preserve a talking-head overlay. Keep the user's identity spellings in one project variable and propagate to all visible labels.

## Sound choices

Use a soft contact cue when an object lands, a short input cue for a demonstrated entry, or a completion cue for a meaningful result. Avoid a sound on every word or every character. A sound list should identify the visible event and its anchor, source or synthesis method, and level relative to speech. Prefer a few clear cues to a continuous layer that competes with narration.
